# Architecture & Design: Historical EDF Import & SomnoBridge BLE Integration

- **Status:** Draft / Working Copy
- **Target:** `SomnoTrace` (ESP32-S3 firmware)
- **Companion Firmware:** `SomnoBridge` (`/opt/shared/somnopal`, ESP32-S3-GEEK Wi-Fi ↔ BLE bridge for EZShare SD cards)
- **Last Updated:** 2026-10-25

## 1. Executive Summary & Core Architectural Decision

SomnoTrace is designed around a single internal source of truth on the microSD card:
- **Authoritative Raw Store:** `/somnotrace/.somnotrace/sessions/`
  - Per-session waveforms, events, and metadata in `streams/<YYYYMMDD>/<session_id>_*.{snt,json}`
  - Per-day summary records and settings in `summaries/<YYYYMMDD>.{spool,settings.json}`
- **Derived Export Tree:** `/somnotrace/SDCARD/` (`DATALOG/<YYYYMMDD>/*.edf`, `STR.edf`, `Identification.json`, `SETTINGS/CurrentSettings.json`), which is deterministically generated by `edf_gen` from `.somnotrace/sessions/` using each session's `clock_drift_ms`, scored by `somno_ml` (SomnoStage), and uploaded by `upload_sched` to all configured backends (SMB, SleepHQ, Aerivue, BreathingRoom).

To support both **(A) manual/FTP historical EDF imports** (from an AirSense 10 or AirSense 11) and **(B) automated EZShare → SomnoBridge → SomnoTrace BLE pulls** without duplicating downstream logic or breaking the "Recreate EDFs" / dashboard / SomnoStage invariants, both pathways converge on a **single unified staging directory (`/somnotrace/IMPORT/`)** and a **single EDF-to-SNT Import Engine (`edf_import`)**:

### Why Unified Staging (`/somnotrace/IMPORT/`) Works Best for Both Paths
1. **Single Parser & Converter:** SomnoBridge downloads raw EDF bytes from EZShare without modifying them. Staging completed SomnoBridge downloads into `/somnotrace/IMPORT/DATALOG/<YYYYMMDD>/` alongside a small `<day>/_bridge_drift.json` sidecar means `edf_import` handles both manual/FTP drops and SomnoBridge pulls with the exact same code path.
2. **Crash Recovery for Free:** If SomnoTrace loses power after pulling 5 MB of EDFs over BLE from SomnoBridge but before converting them to `.snt`, the files are already on disk in `/somnotrace/IMPORT/` and are automatically imported on the next boot without re-transferring over BLE.
3. **Top-Level Visibility:** `/somnotrace/IMPORT` appears as `/IMPORT` at the root of the SD card and at the root of the anonymous/authenticated FTP server — easy for users to find when copying files from a PC.

## 2. Staging Directory Layout & File Lifecycle

### 2.1 Accepted Layouts in `/somnotrace/IMPORT/`

Users copying files manually (via SD card reader or FTP) may copy an entire ResMed SD card root, individual `DATALOG/YYYYMMDD/` day folders, or loose session EDFs. The scanner in `edf_import` accepts all three layouts:

1. **Full ResMed Card Layout (AS10 or AS11, also used by SomnoBridge staging):**
   ```
   /somnotrace/IMPORT/
     Identification.json              (AS11) or Identification.tgt (AS10)
     STR.edf                          (optional multi-day summary)
     SETTINGS/
       CurrentSettings.json           (AS11, optional)
     DATALOG/
       20261020/
         20261020_231502_EVE.edf
         20261020_231502_CSL.edf
         20261020_231509_BRP.edf
         20261020_231509_PLD.edf
         20261020_231509_SA2.edf      (or _SAD.edf on AS10)
         _bridge_drift.json           (written by SomnoBridge client only)
   ```
2. **Day-Folder Layout:**
   ```
   /somnotrace/IMPORT/
     20261020/
       20261020_231509_BRP.edf
       ...
   ```
3. **Flat / Loose Files Layout:**
   ```
   /somnotrace/IMPORT/
     20261020_231509_BRP.edf
     20261020_231509_PLD.edf
     ...
   ```
   *(For loose files without a parent `YYYYMMDD` folder, `edf_import` derives the raw noon-day folder `YYYYMMDD` from the filename timestamp `YYYYMMDD_HHMMSS` using the noon-to-noon rule: timestamps before `12:00:00` belong to the previous calendar date's noon-day.)*

### 2.2 Quiescence & Triggering Rules (Preventing Mid-Copy Imports)

Because FTP uploads and SomnoBridge BLE transfers write multiple files over several seconds or minutes, `edf_import` must never ingest a half-uploaded session:

1. **In-Flight Temp Suffix (`.part` / `.tmp`):**
   - SomnoBridge BLE downloads write to `<filename>.edf.part` and only `rename()` to `<filename>.edf` after `STREAM_END` reports `ok && completion_allowed && source_unchanged` and the raw SHA-256 matches.
   - Any file ending in `.part` or `.tmp` is ignored by the import scanner, and its presence in a day folder marks that day as "still transferring".
   - **Recency window (`IMPORT_QUIESCE_SEC = 15`, implemented in `edf_import.c`):** a unit (root files, a day group, or its `_bridge_drift.json`) whose files were modified less than 15 s ago is deferred (`edf_import_unit_t.deferred`); the worker re-checks every 3 s and gives up after 30 min. Files dated in the future (device clock not yet set) never count as recent; `edf_import_ctx_set_quiesce(ctx, 0)` turns the window off for an explicit "import now" trigger. Because FATFS only refreshes a file's size/mtime on close, the worker also holds off while `ftp_getstate()` reports an FTP upload in progress (`E_FTP_STE_CONTINUE_FILE_RX`).
2. **Trigger Sources:**
   - **Boot scan:** After `sd_storage_init()` and `session_writer_enable_deferred_export()`, the background import worker checks `/somnotrace/IMPORT/` for files left by an offline microSD copy or an interrupted pre-reboot run.
   - **FTP settle hook / periodic check:** While FTP has an active client connection or open write file (`ftp_getstate()`), automatic import is held off. Once FTP disconnects (or no file in `/somnotrace/IMPORT/` has been modified for `IMPORT_QUIESCE_SEC = 15` seconds), the import worker runs.
   - **Explicit Web UI / HTTP API trigger:** `POST /api/import/run` triggers an immediate scan and import pass.
   - **SomnoBridge sync completion hook:** After `sb_ble` finishes downloading a day's files + `_bridge_drift.json` + root bundle, it directly invokes the import worker for the staged day(s).

### 2.3 Deletion & Cleanup Lifecycle (Requirement 3)

Imported EDFs in `/somnotrace/IMPORT/` are transient staging inputs and are deleted once converted to `.snt` format:

1. **Per-Session Atomic Commit Before Delete:**
   - For a given session in day `YYYYMMDD`, `edf_import` writes all `.snt` files (`_flow.snt`, `_press.snt`, `_flow_mm.snt`, `_sa2.snt`, `_pld.snt`, `_events.snt`), metadata (`_ident.json`, `_settings.json`), and finally `<session_id>_session.json` (via `.tmp` + `fflush` + `fsync` + `rename`).
   - **Only after `<session_id>_session.json` is durably on disk** does `edf_import` `unlink()` the source EDF files (`_BRP.edf`, `_PLD.edf`, `_SA2.edf`/`_SAD.edf`, `_EVE.edf`, `_CSL.edf`) that formed that session.
2. **Per-Day & Root Cleanup:**
   - Once all sessions in `IMPORT/DATALOG/<YYYYMMDD>/` have been imported and unlinked, `_bridge_drift.json` is unlinked and the empty `IMPORT/DATALOG/<YYYYMMDD>` directory is removed via `rmdir()`.
   - Once all staged day folders in the batch are processed and `IMPORT/STR.edf`, `IMPORT/Identification.*`, and `IMPORT/SETTINGS/*` have been ingested into `.somnotrace/sessions/summaries/` and `device_metadata.json`, those root staging files are unlinked as well, leaving `/somnotrace/IMPORT/` clean.
3. **Corrupt / Unparseable Files:**
   - If a file in `/somnotrace/IMPORT/` fails EDF header validation or has a truncated record body, it is **not** silently converted into corrupt `.snt` data; `edf_import` logs a clear error, records the failure in `/api/import/status`, and moves/renames the bad file to `<name>.bad` (or deletes it if 0 bytes) so it does not loop forever.

## 3. EDF-to-SNT Conversion Specification (`edf_import`)

### 3.1 Session Clustering: Reconciling `TherapyStart` vs `MaskOn` Timestamps

On both AirSense 10 and AirSense 11 SD cards, files for a single therapy session can carry **two slightly different filename/header timestamps**:
- `EVE.edf` and `CSL.edf` are stamped at **`TherapyStart`** (`t_eve`, when the blower starts).
- `BRP.edf`, `PLD.edf`, and `SA2.edf`/`SAD.edf` are stamped at **`MaskOn` / `_ZLE` rising edge** (`t_wav`, when gated patient flow begins, typically `0` to `15` seconds after `t_eve`).
  *(Example from real AS11 capture in `.ai/2min-lost/STR/DATALOG/20260715/`: `20260715_233914_EVE.edf` + `20260715_233914_CSL.edf` paired with `20260715_233923_BRP.edf` + `20260715_233923_PLD.edf` + `20260715_233923_SA2.edf` — a 9-second delta.)*

**Clustering Algorithm per Day Folder:**
1. Scan all `YYYYMMDD_HHMMSS_<KIND>.edf` files in the day folder (`KIND` ∈ `{BRP, PLD, SA2, SAD, EVE, CSL}`, case-insensitive).
2. Group waveform files (`BRP`, `PLD`, `SA2`/`SAD`) that share the same timestamp `t_wav` (or within ±2 s) into a waveform cluster.
3. Group annotation files (`EVE`, `CSL`) that share the same timestamp `t_eve` (or within ±2 s) into an annotation cluster.
4. Match each annotation cluster `t_eve` to a waveform cluster `t_wav` when `0 <= (t_wav - t_eve) <= 60 s` and no other cluster lies between them.
   - Unmatched annotation-only clusters (e.g. an unmasked run where only `EVE`+`CSL` were written by the CPAP) or waveform-only clusters remain standalone sessions.

**Alignment with `edf_gen` (Zero Data Loss on Re-Export):**
- Recall how `edf_gen.c` works when exporting a session from `.somnotrace/sessions/streams/<YYYYMMDD>/`:
  - `edf_gen` uses `start_epoch_ms` for `EVE.edf`/`CSL.edf` filenames and headers.
  - `edf_gen` searches `<session_id>_events.snt` for `_ZLE` rising edge or `MaskOn`. If found at `maskon_ntp > start_epoch_ms`, `edf_gen` skips `brp_skip = (maskon_ntp - start_epoch_ms) * 25 / 1000` samples from `_flow.snt`, `_press.snt`, `_sa2.snt`, and `_pld.snt`, and stamps `BRP`/`PLD`/`SA2` with `maskon_ntp`.
  - However, in an imported `BRP.edf`/`PLD.edf`/`SA2.edf`, **the CPAP already discarded pre-MaskOn samples** — sample 0 of `BRP.edf` starts at `t_wav` (`MaskOn`), NOT at `t_eve` (`TherapyStart`)!
- Therefore, how should `edf_import` align `t_eve` and `t_wav`?
  - **If `t_wav == t_eve` (or only waveforms exist):**
    - `t_session_dev_ms = t_wav_ms`. No `MaskOn` offset exists (`brp_skip = 0`).
  - **If `t_wav > t_eve` (e.g. `t_wav` is 7–15 s after `t_eve`):**
    - We want `edf_gen` to emit `EVE.edf`/`CSL.edf` at `t_eve + drift` AND `BRP.edf`/`PLD.edf`/`SA2.edf` at `t_wav + drift` without discarding the first `t_wav - t_eve` seconds of real waveform samples from `BRP.edf`!
    - Two clean ways to achieve this:
      1. **Option 1 (Zero SNT padding, recommended):** Record `"waveform_offset_ms": (t_wav_ms - t_eve_ms)` (or `"pre_gated": true`) in `<session_id>_session.json` and emit a synthetic `MaskOn` event at `t_wav_ms` in `_events.snt`. In `edf_gen.c`, when `"pre_gated": true` is present in `_session.json` (or via a flag), `edf_gen` sets `maskon_start_ms = zle_or_maskon_ntp` (so `BRP`/`PLD`/`SA2` get the exact `t_wav + drift` filename and header!) while keeping `brp_skip = sa2_skip = pld_skip = 0` because the `.snt` files already start at `MaskOn`!
      2. **Option 2 (Zero `edf_gen.c` changes):** Prepend `(t_wav_ms - t_eve_ms)` of `SNT_MISSING_V2` (`INT16_MIN`) / baseline samples (at most 15 s = 375 samples = 750 bytes in `_flow.snt`) before `BRP.edf`'s samples, set `start_epoch_ms = t_eve_ms + drift`, and write a `MaskOn` event at `t_wav_ms` in `_events.snt`. When `edf_gen.c` runs unmodified, it sees `MaskOn` at `t_wav_ms`, skips those exact prepended samples (`brp_skip`), and writes `EVE`/`CSL` at `t_eve + drift` and `BRP`/`PLD`/`SA2` at `t_wav + drift`!
    - **Recommendation:** Use **Option 1** (with a 5-line check in `edf_gen.c` so `_flow.snt` start time in `snt_header_t` is `t_wav_ntp` and no dummy samples appear in dashboard graphs), while emitting `MaskOn` at `t_wav_ms` and `MaskOff` at `t_wav_ms + dur_ms` in `_events.snt` so `edf_summary.c`'s `collect_session_mask_pairs()` also sees the exact mask window!

### 3.2 EDF Header & Signal Table Parser

Every imported `.edf` file is parsed and validated before reading records:
1. **Fixed Header (256 bytes):**
   - `version` (bytes `0..7`): must be `"0       "`.
   - `patient_id` (bytes `8..87`): contains `"X X X X <H1> <H2>"` on ResMed files.
   - `recording_id` (bytes `88..167`): e.g. `"Startdate 22-OCT-2026 X X X SRN=22251436648 MID=46 VID=3"`. Extract `SRN`, `MID`, `VID` via key-value scan.
   - `startdate` (`168..175`, `"dd.mm.yy"`) and `starttime` (`176..183`, `"hh.mm.ss"`): parsed into civil local time (`struct tm` with `tm_isdst = -1` via `mktime()`, or using the device's known UTC offset if `TimeZoneOffset` was parsed from settings).
   - `header_bytes` (`184..191`): must equal `256 * (1 + n_signals)`.
   - `reserved` (`192..235`): `"EDF"` (continuous waveform/summary) or `"EDF+D"` / `"EDF+C"` (annotations).
   - `n_records` (`236..243`), `record_duration` (`244..251`), `n_signals` (`252..255`).
   - `record_duration` is `0.00` for the `EDF+D` EVE/CSL files of real cards (one record per annotation, each led by its own `+0\x14\x14\x00` time-keeping TAL); it must be `> 0` only for waveform/summary files. A parser that insists on a positive duration silently drops every respiratory event.
2. **Per-Signal Header Blocks (`256 * n_signals` bytes):**
   - Extract for each signal `i ∈ [0, n_signals)`:
     - `label[16]` (trimmed of trailing spaces)
     - `unit[8]`
     - `phys_min`, `phys_max` (`double`)
     - `dig_min`, `dig_max` (`int`)
     - `samples_per_record` (`int`)
   - Compute `record_bytes = sum(samples_per_record[i] * 2)`.
   - Validate file size: `stat.st_size >= header_bytes`. If `n_records > 0` and `stat.st_size < header_bytes + n_records * record_bytes`, clamp `n_records = (stat.st_size - header_bytes) / record_bytes` with a warning (handling torn/incomplete SD writes gracefully).

### 3.3 Waveform Conversion (`EDF Digital → SNT v2 int16`)

In SomnoTrace's SNT v2 format (`snt_format.h`), every sample is a little-endian `int16_t` equal to **`lrint(physical_value * 100.0)`**, with `SNT_MISSING_V2 = INT16_MIN (-32768)` as the missing/invalid sentinel.

Given an EDF signal with `(phys_min, phys_max, dig_min, dig_max)` and an EDF digital sample `int16_t dig`:
```c
static inline int16_t edf_dig_to_snt(int16_t dig, const edf_sig_info_t *sig, bool invalid_passthrough)
{
    if (invalid_passthrough && dig == -1) {
        return SNT_MISSING_V2;
    }
    double dspan = (double)(sig->dig_max - sig->dig_min);
    if (dspan == 0.0) return 0;
    double phys = sig->phys_min + ((double)dig - (double)sig->dig_min) * (sig->phys_max - sig->phys_min) / dspan;
    /* Unit normalization: if an older model exports Flow or Leak in L/min instead of L/s,
     * convert to L/s first because SNT stores Flow and Leak as (L/s * 100). */
    if (sig->unit_is_l_per_min && (sig->kind == SIG_FLOW || sig->kind == SIG_LEAK)) {
        phys /= 60.0;
    }
    long v = lrint(phys * 100.0);
    if (v > INT16_MAX) v = INT16_MAX;
    if (v <= INT16_MIN) v = INT16_MIN + 1;
    return (int16_t)v;
}
```

### 3.4 Annotation Conversion (`EVE.edf` & `CSL.edf` → `<id>_events.snt`)

`EVE.edf` and `CSL.edf` are `EDF+D` files where each record contains Time-stamped Annotations Lists (TALs) in the format:
`+<record_onset>\x14\x14\x00+<event_onset>\x15<duration>\x14<label>\x14\x00`

1. **Reverse Label Mapping (EDF+ TAL label → AS11 JSON event name):**
   - In `EVE.edf`:
     - `"Obstructive Apnea"` → `"ObstructiveApneaEnd"`
     - `"Central Apnea"` → `"CentralApneaEnd"`
     - `"Hypopnea"` → `"HypopneaEnd"`
     - `"Arousal"` (or `"RERA"`) → `"ReraEnd"`
     - `"Apnea"` (or `"Unclassified Apnea"`) → `"ApneaEnd"`
     - `"Recording starts"` → skipped (`edf_annotations.c` always emits Record 0 `"Recording starts"` automatically).
   - In `CSL.edf`:
     - `"CSR Start"` → `"CsrStart"`
     - `"CSR End"` → `"CsrEnd"`
     - `"Recording starts"` → skipped.
2. **Timestamp Reconstruction (Exact Inverse of `edf_annotations.c:157`):**
   - Recall `edf_annotations.c:157`:
     ```c
     int64_t event_ntp_ms = as11_ts_ms + clock_drift_ms - (backdate_sec * 1000);
     int64_t onset_sec = (event_ntp_ms - session_start_ms) / 1000;
     ```
   - Since `session_start_ms == t_session_dev_ms + clock_drift_ms`, setting:
     `as11_ts_ms = t_session_dev_ms + (int64_t)llround(tal_onset_sec * 1000.0)`
     (and `backdateSeconds = 0` for imported `CSL` events, since the TAL onset in `CSL.edf` already has `backdateSeconds` subtracted!) guarantees that when `edf_annotations.c` runs:
     `(as11_ts_ms + clock_drift_ms - session_start_ms) / 1000 == tal_onset_sec`!
3. **JSON-Line Output to `<id>_events.snt`:**
   - First line: synthetic `MaskOn` at `t_wav_dev_ms` and `MaskOff` at `t_wav_dev_ms + dur_ms` (so `edf_summary.c:collect_session_mask_pairs()` and `edf_gen.c` know the exact mask-on/off window).
   - Subsequent lines: `{"method":"EventNotification","params":{"dataId":"TherapyEvents-RespiratoryEvents","events":[{"event":"<mapped_name>","reportTime":"<ISO8601_UTC_of_as11_ts_ms>","durationSeconds":<dur>}]}}`.

### 3.5 Identification, Settings & Summary (`STR.edf`) Conversion

#### 3.5.1 Identification (`_ident.json` & `device_metadata.json`)
`edf_import` resolves device identification in priority order:
1. **`IMPORT/Identification.json` (AS11):** Unwraps `FlowGenerator.IdentificationProfiles.{Product,Hardware,Software}` into the flat `<session_id>_ident.json` object expected by `edf_generate_identification_files()`.
2. **`IMPORT/Identification.tgt` (AS10):** Parses ResMed `.tgt` lines (`#SRN`, `#PNA`, `#PCD`, `#MID`, `#VID`, `#CID`, `#SID`, `#RGN`) into the flat `_ident.json` schema:
   - `#SRN` → `"SerialNumber"`
   - `#PCD` → `"ProductCode"`
   - `#PNA` → `"ProductName"` (e.g. `"AirSense 10 AutoSet"`)
   - `#MID` → `"PlatformIdentifier"` (integer)
   - `#VID` → `"VariantIdentifier"` (integer)
3. **EDF Fixed Header `recording_id` Fallback (Always Present):**
   - If neither `Identification.json` nor `Identification.tgt` was provided, parses `SRN=<srn> MID=<mid> VID=<vid>` directly from bytes `88..167` of the session's first `.edf` header and synthesizes `<session_id>_ident.json` (inferring `"ProductName": "AirSense 10"` when `MID < 40` or `"AirSense 11"` when `MID >= 40`).
   - This guarantees `edf_gen.c:450` (`if (!ident)`) **never** aborts on a bare EDF import.

#### 3.5.2 Settings (`_settings.json` & `summaries/<day>.settings.json`)
1. If `IMPORT/SETTINGS/CurrentSettings.json` exists (AS11), unwraps `FlowGenerator` into `<session_id>_settings.json` and `summaries/<day>.settings.json`.
2. Otherwise, if `IMPORT/STR.edf` exists and covers the session's noon-day (or closest day), reconstructs the `SettingProfiles` JSON tree from the `STR.edf` record's `Mode` and `S.*` signals (inverting `build_str_data_values()` in `edf_summary.c`, accounting for AS10 0-indexed vs AS11 1-indexed enums using `MID` per `spec/0002-edf-export.md` §4.3.4).
3. Otherwise, falls back to existing `device_metadata.json` or writes a minimal `{"SettingProfiles":{}}` object.

#### 3.5.3 Multi-Day Summary (`IMPORT/STR.edf` → `summaries/<YYYYMMDD>.spool`)
Why convert `IMPORT/STR.edf` into per-day `.somnotrace/sessions/summaries/<YYYYMMDD>.spool` files?
- `edf_generate_str_edf()` builds `/somnotrace/SDCARD/STR.edf` by scanning `.somnotrace/sessions/summaries/*.spool` (up to 365 days) and looking up each day's `clock_drift_ms` from `.somnotrace/sessions/streams/<day>/*_session.json`.
- `/api/summary?date=YYYYMMDD` on the web dashboard also reads `.somnotrace/sessions/summaries/<YYYYMMDD>.spool` to render daily AHI, pressure, leak, and usage cards.
- **When `IMPORT/STR.edf` is present:**
  - For each daily record in `IMPORT/STR.edf`:
    1. Read signal `Date` (days since 1970-01-01) → compute `YYYYMMDD` noon-day label and nominal `PeriodStart` (`noon_epoch_ms`) / `PeriodEnd` (`noon_epoch_ms + 86400000`).
    2. Read `MaskOn[0..19]` and `MaskOff[0..19]` (in minutes from local noon) → encode protobuf `SUM_F_SESSION_MODE` (field 6) entries with `ts = noon_epoch_ms + MaskOn[k] * 60000` and `duration_min = MaskOff[k] - MaskOn[k]`.
       *(Note: Because `MaskOn` in `IMPORT/STR.edf` is in the raw device clock domain, storing `ts` in the raw device clock domain means `edf_summary.c:895` (`event_ntp_ms = ts + clock_drift_ms`) will automatically apply SomnoBridge's `clock_drift_ms` when regenerating `STR.edf`!)*
    3. Invert `spool_to_edf()` for all present summary stat signals (`Duration`, `AHI`, `HI`, `AI`, `OAI`, `CAI`, `UAI`, `RIN`, `CSR`, `MaskPress.50/95/Max`, `TgtIPAP`, `TgtEPAP`, `Leak.50/70/95/Max`, `MinVent`, `RespRate`, `TidVol`, `SpO2`, `BlowPress`, `Flow`, `AmbHumidity`, `HumTemp`, `HTubeTemp`, etc.) by matching signal labels in `IMPORT/STR.edf`'s header, and write `.somnotrace/sessions/summaries/<YYYYMMDD>.spool` (unless a native BLE-captured `.spool` with `ClockB` already exists for that day and is newer).
- **When `IMPORT/STR.edf` is NOT present:**
  - For each imported day `YYYYMMDD` that has no `<YYYYMMDD>.spool` file, `edf_import` synthesizes a `<YYYYMMDD>.spool` record from the day's imported sessions:
    - `PeriodStart`, `PeriodEnd`, `SessionModeEntries` (from each session's start/duration), `Duration` (sum of session minutes),
    - `OAI`, `CAI`, `HI`, `UAI`, `RIN`, `AI`, `AHI`, `CSR` computed from `<id>_events.snt` event counts divided by total therapy hours,
    - `MaskPress`, `Leak`, `RespRate`, `TidVol`, `MinVent` 50th/95th/max percentiles computed from `<id>_pld.snt` samples!
  - This ensures that even if a user only drops a single day folder of EDFs without `STR.edf`, both `/somnotrace/SDCARD/STR.edf` and the web portal's Daily Summary card work completely!

## 5. SomnoBridge BLE Client Architecture (`sb_ble`)

### 5.1 Mutually Exclusive CPAP BLE Source (`AS11` vs `SomnoBridge`)

SomnoTrace has two BLE connection budgets in NimBLE (`CONFIG_BT_NIMBLE_MAX_CONNECTIONS=2`):
1. **Slot 1 — CPAP Source:** Either **AirSense 11** (`as11_ble`) **or** **SomnoBridge** (`sb_ble`).
2. **Slot 2 — Oximeter:** **O2 Ring** (`oximeter`, Gen2 OxyII or Gen1 Legacy).

Following the same dispatcher pattern as `oximeter.c`, CPAP BLE operations route through a thin dispatcher (or mode switch in `as11_ble` / `cpap_ble`) persisted in NVS (`namespace "as11"`, key `"drv_type"`: `0 = AS11`, `1 = SOMNOBRIDGE`):

- **Unified BLE Scan (`GET /api/ble/scan`):**
  - During a single 6-second active BLE scan, the GAP discovery callback collects advertisements matching **either**:
    - **AirSense 11:** Service UUID `0xfd56` or name prefix `"ResMed"` → emitted in scan JSON with `"type": "as11"`.
    - **SomnoBridge:** Service UUID `8ba7d100-6e4b-4bb4-9f1d-7306766e6f50` or name prefix `"SomnoBri"` (`SomnoBridge` is truncated to `"SomnoBri"` in the 31-byte adv packet) → emitted in scan JSON with `"type": "somnobridge"`.
- **Pairing Selection (`POST /api/ble/pair`):**
  - Looks up the selected `addr` in the scan cache (or accepts an optional `"type"` field in the POST body).
  - If `"somnobridge"`, routes to `sb_ble_start_pair(addr)`; if `"as11"`, routes to `as11_ble_start_pair(addr)`.
  - Both transition `/api/status` → `ble.state = "waiting_passkey"`, and `POST /api/ble/confirm` delivers the passkey (4 digits for AS11 SRP-6a; 6 digits for SomnoBridge BLE SM MITM).

### 5.2 NimBLE Security Configuration (`sdkconfig.defaults`)

**Key Finding:**
Currently in `SomnoTrace/sdkconfig.defaults`:
```ini
# CONFIG_BT_NIMBLE_SECURITY_ENABLE is not set
```
because AirSense 11 uses custom application-layer SRP-6a + AES-256-GCM over an unencrypted BLE link, and O2 Ring uses plaintext GATT.
However, **SomnoBridge requires Bluetooth Security Level 4** (`ble_svc.c:124`: `d.sec_state.encrypted && d.sec_state.authenticated && d.sec_state.bonded`, LE Secure Connections + MITM 6-digit passkey displayed on the SomnoBridge LCD).

**Required `sdkconfig.defaults` additions on SomnoTrace:**
```ini
CONFIG_BT_NIMBLE_SECURITY_ENABLE=y
CONFIG_BT_NIMBLE_SM_SC=y
# CONFIG_BT_NIMBLE_SM_LEGACY is not set
CONFIG_BT_NIMBLE_MAX_BONDS=2
```
And in `as11_ble_init()` (shared NimBLE host setup):
```c
ble_hs_cfg.sm_io_cap = BLE_SM_IO_CAP_KEYBOARD_ONLY;
ble_hs_cfg.sm_bonding = 1;
ble_hs_cfg.sm_mitm = 1;
ble_hs_cfg.sm_sc = 1;
ble_hs_cfg.sm_our_key_dist = BLE_SM_PAIR_KEY_DIST_ENC | BLE_SM_PAIR_KEY_DIST_ID;
ble_hs_cfg.sm_their_key_dist = BLE_SM_PAIR_KEY_DIST_ENC | BLE_SM_PAIR_KEY_DIST_ID;
ble_store_config_init();
```
- **Zero impact on AS11 and O2 Ring:** In BLE, security is only initiated when a central calls `ble_gap_security_initiate()` or a peripheral returns `BLE_ATT_ERR_INSUFFICIENT_AUTHEN`. Neither AS11 nor O2 Ring requests SMP security, so their connections remain unencrypted at the link layer exactly as before.
- **SomnoBridge Pairing Handshake:**
  1. User short-presses BOOT on SomnoBridge (`PAIRING 120S` opens on SomnoBridge LCD).
  2. User clicks **Scan** → **Pair** on SomnoBridge in SomnoTrace Web UI.
  3. `sb_ble` connects, negotiates MTU 247 + 2M PHY + DLE, and calls `ble_gap_security_initiate(conn_handle)`.
  4. SomnoBridge generates a 6-digit PIN on its LCD; NimBLE on SomnoTrace fires `BLE_GAP_EVENT_PASSKEY_ACTION` with `action == BLE_SM_IOACT_INPUT`.
  5. `sb_ble` sets state to `AS11_STATUS_WAIT_PASSKEY` (`"waiting_passkey"`).
  6. User enters the 6-digit PIN in the SomnoTrace Web UI (`POST /api/ble/confirm`), which calls `ble_sm_inject_io(conn_handle, &(struct ble_sm_io){ .action = BLE_SM_IOACT_INPUT, .passkey = pin })`.
  7. `BLE_GAP_EVENT_ENC_CHANGE` fires with `encrypted=1, authenticated=1, bonded=1`. `sb_ble` saves the peer identity in NVS (via `nvs_writer`), subscribes to `Control` CCCD (`0x0002` indications) and `Data` CCCD (`0x0001` notifications), and enters `"paired"`.

### 5.3 SomnoBridge Wire Protocol & v2 Stream Decoder

`sb_ble.c` implements the client side of `somnopal/docs/ble-api.md` (mirroring the reference logic in `somnopal/scripts/ble_query.py`):

1. **GATT Topology:**
   - Service: `8ba7d100-6e4b-4bb4-9f1d-7306766e6f50`
   - Control Char: `8ba7d101-6e4b-4bb4-9f1d-7306766e6f50` (Requests written via Write / Write-Without-Response; JSON responses and `TIME_REPLY` received via **Indications**)
   - Data Char: `8ba7d102-6e4b-4bb4-9f1d-7306766e6f50` (Stream bytes received via **Notifications**)
2. **Control Framing & Reassembly (`16-byte blep_hdr_t`):**
   - Header: `u8 ver(=1) | u8 kind | u16 flags | u32 request_id | u64 offset`
   - Fragment reassembly into a 8 KiB PSRAM buffer (`GET_DRIFT` responses can be up to ~4–8 KiB).
   - Follows `ble-api.md` §7 dedup rules: ignore fragments for already-completed `request_id`s unless `offset == 0 && (flags & FLAG_START)` (which heals a poisoned first `STREAM_END` using the redundant second `STREAM_END` sent 300 ms later).
3. **Time-Sync Anchor Exchange (`TIME_REQUEST` / `TIME_REPLY` / `TIME_COMMIT`):**
   - Whenever SomnoTrace has valid NTP time (`time_sync_is_synced()`):
     - Runs a 5-round exchange on connection establishment and every **10 minutes** while connected.
     - Sends `TIME_REQUEST` (`t1_utc_us`, `src_uncertainty_us = 25000`, `source_epoch`), records receipt `t4_utc_us` on `TIME_REPLY`, picks the round with the lowest RTT (`(t4 - t1) - (m3 - m2)`), and commits it via `TIME_COMMIT`.
     - This feeds SomnoBridge's `drift` module with qualified UTC anchors (`src_uncertainty_us <= 100 ms`) so SomnoBridge can produce `qualified` / `provisional` drift estimates during therapy!
4. **High-Speed v2 File Streaming (`GET_FILE` with `"v2": true`):**
   - Grants initial credit window (`STREAM_WINDOW = 48 * 240 = 11,520` bytes) via `BLEP_ACK` (kind 4, write-without-response) immediately upon receiving `STREAM_BEGIN`.
   - Advances the right-edge credit window proactively every ~2,880 wire bytes received.
   - Decodes compact 4-byte `STREAM_DATA` frames (`ver=1, kind=10, u16 seq`), dropping duplicate backward `seq` frames and counting any sequence gaps.
   - Parses 12-byte self-describing block headers (`u8 codec | u8 ver | u16 rsv | u32 raw_len | u32 enc_len`, `raw_len <= 64 KiB`):
     - `codec == 0`: raw passthrough
     - `codec == 1`: raw deflate (`tinfl_decompress_mem_to_Horizontal` / ESP ROM `tinfl` or zlib raw inflate into a 64 KiB PSRAM block buffer)
     - `codec == 2`: raw deflate followed by in-place `uint16_t` prefix-sum (`x[i] = x[i] + x[i-1]`) inverse delta16
   - Updates running `mbedtls_sha256_context` over the decoded raw bytes and writes directly to `/somnotrace/IMPORT/.../<name>.part`.
   - On `STREAM_END`: verifies `ok == true`, `completion_allowed == true`, `source_unchanged == true`, `monitoring_checked == true`, `actual_bytes == decoded_bytes`, `seq_errors == 0`, and `sha256` match before renaming `.part` → `.edf`.

### 5.4 SomnoBridge Sync Scheduler & Persistent Ledger

SomnoBridge's catalog is volatile in PSRAM; per `somnopal/docs/tracking.md` §1, **SomnoTrace is the sole persistent sync authority**.

1. **Persistent Download Ledger (`/somnotrace/.somnotrace/sessions/bridge_ledger.json`):**
   - Tracks synced DATALOG files so SomnoTrace never re-pulls unchanged files over BLE after `.snt` conversion and deletion of `/somnotrace/IMPORT/` staging files:
     ```json
     {
       "v": 1,
       "root": {
         "STR.edf": { "size": "27184", "ts": "2026-10-24 07:38:00" },
         "Identification.json": { "size": "764", "ts": "2026-10-01 12:00:00" },
         "CurrentSettings.json": { "size": "2441", "ts": "2026-10-24 07:38:00" }
       },
       "days": {
         "20261023": {
           "20261023_232447_EVE.edf": { "size": "1024", "ts": "2026-10-23 13:24:48" },
           "20261023_232454_BRP.edf": { "size": "2678784", "ts": "2026-10-23 21:38:14" }
         }
       }
     }
     ```
   - Notice: Comparison uses `(day, name, listed_size, ts)` from `LIST_DAY`. If a session resumes after a toilet break, `listed_size` or `ts` changes on SomnoBridge → the tuple no longer matches `bridge_ledger.json` → SomnoTrace automatically re-downloads the grown file, re-imports the session (overwriting the shorter `.snt` files), and triggers `edf_gen_rebuild_day(day)`!
2. **Sync State Machine (`sb_sync_task`):**
   - **Poll Cadence:** Every 30 seconds while connected:
     - Sends `GET_STATUS`.
     - Updates SomnoTrace's live therapy indicator (`bsp_display` / MQTT / `therapy_alert`): when `therapy.state == 1` (`THERAPY_IN`), SomnoTrace knows therapy is active!
   - **Sync Trigger:** Runs when `therapy.transfer_allowed == true` (`state == THERAPY_OUT` and `!stale`) and either:
     - Therapy just transitioned from `THERAPY_IN` → `THERAPY_OUT`,
     - Initial boot / reconnect sync has not run yet,
     - Periodic idle check (every 5 minutes) sees new catalog activity, or
     - User clicks **"Sync Now"** in the Web UI.
   - **Sync Execution Order:**
     1. Call `LIST_RECENT_DAYS {"days": 14}` (configurable; or `365` on manual "Full Sync").
     2. For each returned `day`, call `LIST_DAY {"day": day}` and diff `files[]` against `bridge_ledger.json`.
     3. If any days have new/changed files:
        - Call `PREPARE_DAYS {"days": [...]}` to pre-warm SomnoBridge's 90 s freshness guard; if `eta_ms > 0`, wait `eta_ms`.
        - Refresh root/settings metadata first (`LIST_DIRECTORY "/"` and `LIST_DIRECTORY "/SETTINGS"`), pulling `Identification.json` (or `Identification.tgt`), `SETTINGS/CurrentSettings.json`, and `STR.edf` into `/somnotrace/IMPORT/` if changed.
        - For each day with pending files (newest day first):
          - Sort the day's pending files **smallest first (`EVE`, `CSL`, `SA2`/`SAD`, `PLD`) and `BRP` last** (per SomnoBridge spec §12.2).
          - Download each file via `GET_FILE {"directory": "/DATALOG/<day>", "name": "<name>", "expected_size": "<size>", "v2": true}`.
          - On `EC_STALE`, sleep 12 s and retry (up to 3 times). On `EC_BUSY`, sleep 1.5 s and retry. On `EC_THERAPY_ACTIVE` / `EC_THERAPY_UNKNOWN`, abort sync immediately and wait for `THERAPY_OUT`.
          - After the day's files are downloaded, call `GET_DRIFT {"best_available": true, "include_provisional": true}` and write `/somnotrace/IMPORT/DATALOG/<day>/_bridge_drift.json`.
          - Invoke `edf_import_day(day)` → converts staged EDFs to `.snt` + `_session.json` + `.spool`, deletes the staged EDFs from `/somnotrace/IMPORT/`, updates `bridge_ledger.json`, and runs `edf_gen_rebuild_day(day)` + `somno_ml_reconcile()` + `uploader_notify_export_complete(day)`.

## 7. Memory, Performance & Reliability Constraints

1. **PSRAM-First Buffers:**
   - All `edf_import` record buffers (~6 KiB per 60 s BRP record) and SomnoBridge v2 stream decompression buffers (64 KiB raw block buffer + 64 KiB compressed input buffer + 8 KiB JSON reassembly buffer ≈ 136 KiB total) are allocated from PSRAM (`heap_caps_malloc(..., MALLOC_CAP_SPIRAM | MALLOC_CAP_8BIT)`) on demand and freed when idle.
   - Internal SRAM impact when idle is < 2 KiB.
2. **Storage Lease & Watchdog Safety:**
   - `edf_import` acquires `SD_LEASE_EXPORT` per session/day import and yields (`vTaskDelay(1)`) every few EDF records so the task watchdog and HTTP/BLE tasks are never starved during multi-megabyte historical imports.
   - If a live therapy session starts while a historical import is running (`sd_storage_recording_active()`), `edf_import` pauses between sessions so live capture always has priority.
